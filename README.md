# Диспетчер заявок

Веб-приложение для регистрации и обработки обращений. Пользователь создаёт, просматривает, изменяет и удаляет заявки. Уведомления о создании заявок формируются отдельным фоновым обработчиком. Повторное чтение списка ускоряется с помощью Redis.

## Состав приложения

| Компонент | Технология | Назначение |
|---|---|---|
| frontend | Nginx, HTML, JavaScript | Интерфейс и передача HTTP-запросов в API |
| api | Python, FastAPI | Операции с заявками, кэширование и публикация событий |
| worker | Python | Потребление событий и создание уведомлений |
| db | PostgreSQL 16 | Основное хранение данных |
| db-standby | PostgreSQL 16 | Потоковая реплика основной БД |
| redis | Redis 7 | Кэш списка заявок |
| nats1–nats3 | NATS JetStream 2.11 | Хранение и доставка событий с тремя репликами потока |
| firewall-api и firewall-worker | iptables | Ограничение сетевых соединений приложений |

## Запуск

Требуются Docker Engine или Docker Desktop с Linux-контейнерами, Docker Compose v2, Bash, Python 3 и curl. Ориентир ресурсов для локального запуска: 4 CPU, 6 ГБ памяти для Docker и 8–10 ГБ свободного места.

Из корня проекта:

```bash
bash scripts/start.sh
```

Интерфейс: http://localhost:8080.

При первом запуске создаётся `.env` со случайными паролями. PostgreSQL, Redis и NATS не публикуют порты на хост; веб-порт привязан к `127.0.0.1`. Внутренние сервисы доступны через сети Docker.

## Проверка работы

```bash
python3 scripts/smoke.py
```

Проверка выполняет HTTP CRUD, проверяет чтение кэша, его инвалидацию и получение уведомления от обработчика. Успешный прогон завершается строкой:

```text
PASS: CRUD, cache, invalidation and broker delivery
```

Полный порядок проверки сетевых ограничений, отказов и восстановления приведён в [описании проверок](docs/testing.md).

## Обработка событий

API сохраняет заявку и событие в таблицу outbox одной SQL-транзакцией. Фоновый издатель отправляет событие в JetStream и отмечает подтверждённую публикацию. Worker фиксирует уведомление и идентификатор события в БД, затем отправляет ACK. Повторная доставка не создаёт повторное уведомление благодаря уникальному `event_id`.

## Ограничения

Все компоненты размещаются на одном хосте, поэтому отказ хоста останавливает приложение. Frontend, API, worker и Redis развёрнуты в одном экземпляре. Переключение PostgreSQL выполняется вручную подготовленным скриптом; репликация асинхронная. После повышения standby прежний primary должен оставаться остановленным до восстановления корректной топологии.

Веб-интерфейс не содержит пользовательской аутентификации. TLS для внутренних соединений не настроен. Конфигурация предназначена для доступа через localhost; публичное размещение требует дополнительной настройки защиты.

Файлы `.env`, резервные копии, данные runtime и локальные журналы исключены из Git. Их не следует добавлять в репозиторий вручную.
